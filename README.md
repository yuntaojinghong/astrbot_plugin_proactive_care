# 微光 · 主动关怀

> 让机器人学会先开口。群聊安静太久、话题断在半截、或者今天还没人说话时，它会结合这个群**真实聊过的内容**与**长期记忆**，说一句自然的话——不是群发模板。

## 它解决的是什么问题

群会冷。冷下去之后，通常没人负责开第一句。

现有做法的两条路都不太理想：定时群发同一句文案，很快就会被当成广告；干脆不做，群就一直沉下去。

微光走的是第三条路——**先读懂这个群，再决定说什么**。生成一条消息时它会拿到：

| 喂给模型的东西 | 从哪来 |
| --- | --- |
| 最近若干条真实群聊记录 | 插件自己维护的上下文表（带时间戳） |
| 关于这个群的长期记忆 | 攒批抽取、归一化去重后的记忆库 |
| 当前时间与时段 | 让它不会在半夜说「早上好」 |
| 这次为什么开口 | 触发原因，等于给模型一个说话的理由 |
| 你以前说过的话 | 用于查重，避免「换汤不换药」 |

所以每个群收到的话都不一样，同一天里也不会重复。

## 五种触发方式，各自独立开关

| 触发方式 | 什么情况下开口 | 一句话理解 |
| --- | --- | --- |
| **即时搭话** | 群友一发消息就掷骰子，命中概率就回（默认 25%） | 大家正聊着，跟着接一句 |
| **空闲唤醒** | 群聊静默超过阈值（默认 180 分钟） | 群里没人说话了，接一句 |
| **话题追问** | 机器人提问后没人接话（默认等 30 分钟） | 上一句抛出去的问题自己续一下 |
| **随机关怀** | 每天在允许时段内随机触发 1~3 次 | 就是突然想到你们了 |
| **定时问候** | 你自定义的时刻（如早 8 点、周五下班前） | 到点打个招呼，但内容仍是现生成的 |

轮询类的四种按固定优先级判定：**话题追问 > 定时问候 > 空闲唤醒 > 随机关怀**。第一项优先级最高，因为只有它对应着「有一个明确的对话还没结束」。

### 即时搭话：可调概率的自动回复

如果你想要的是「群友一发消息机器人就有机会回一句」，用这个：

- **概率可调**：`触发 · 即时搭话 → 回复概率`，0~100%。0% 等于关闭，100% 是每条都回（不建议）。也可以在群里直接发 `/主动 概率 30`。
- **每个群可以不一样**：面板「会话」页每个群一个「搭话概率」按钮，留空表示跟随全局。热闹的大群调低、小群调高都很方便。
- **延迟几秒再回**：默认随机延迟 2~8 秒，秒回太像机器人了。
- **独立秒级冷却**：默认两次之间至少隔 300 秒。这一项刻意**不用**全局的分钟级冷却，否则 120 分钟的冷却会让这个功能形同虚设；同时它也是防止群里一热闹就连环刷屏的关键闸门。
- **不看「距最后一条真人消息的最短间隔」**：那条闸门的作用是防止机器人在大家聊得正欢时插话，而即时搭话恰恰就是要在这时候接话，所以对它不适用。

静默时段、每日上限、连续无回应熔断这些仍然照常生效——概率调再高，也不会在半夜刷屏、不会超过每日上限。

## 四层防骚扰（外加两道零成本闸门）

这是这个插件最花心思的部分。每次轮询要过这些条件，全部通过才有资格调用模型：

```
静默时段  →  每日上限  →  冷却间隔  →  距最后一条真人消息的间隔
   ↓            ↓           ↓              ↓
 零成本闸门（先跑，不消耗 token 额度）
   ↓
触发方式判定  →  生成  →  发送
```

再叠加两道保险：

- **每日上限**：每个会话每天最多发 N 条（默认 3），所有触发方式合计。
- **连续无回应熔断**：发出后进入「等待回应」状态。超过回应窗口仍无真人发言就累加一次沉默计数，**连续 3 次之后该群自动暂停**，并在面板里写明原因。这是最后一道保险，防止对着空气自说自话。

另外还有 **演练模式**：打开后所有主动消息只写进日志和面板，不会真的发出去。调参阶段建议先开一两天。

## 记忆机制

长期记忆单独落库，不复用 AstrBot 的对话历史。

- **攒批抽取**：每积累 N 条新消息（默认 30）才调用一次模型抽取，避免逐条烧 token。
- **归一化去重**：去标点、去空白、转小写之后做唯一键。同一件事说两遍不会存成两条，而是保留较高的重要度。
- **排序检索**：`重要度 × 时间衰减 + 与当前话题的二元字组重叠度 + 历史命中次数`。越久远的记忆排序越靠后但**不删除**，最近聊到的内容会浮上来。
- **可视化维护**：面板里可以查看、搜索、手动添加、改写、删除、清空、手动触发整理。

抽取用的是「严格 JSON 输出 + 容错解析」：模型返回代码块、夹带解释文字、甚至退化成项目符号列表，都能被正确解析；实在解析不出来就丢弃，绝不让「模型今天不想干活」这种句子变成一条记忆。

## 与匿名树洞类插件共存

两个插件装在一起，最怕互相打架——或者更糟，把匿名内容泄露出去。微光从**数据入口**做了三重隔离，不需要对方配合：

1. **只跟踪群聊**。匿名投稿的原始消息走的是私聊，微光默认完全不开私聊通道，在数据层面根本接触不到投稿原文，因此不存在反匿名化的可能。
2. **忽略机器人自己发出的消息**。树洞类插件是靠机器人账号把内容转发到群里的，发送者就是机器人自己。这条规则把转发帖整体挡在统计之外——**不会让树洞每发一帖就把空闲计时器清零**，空闲唤醒依然能正常触发。
3. **昵称池与格式兜底**。把树洞用的昵称池填进配置（如 `番茄,苹果,橘子`），命中即跳过；留空时按内置的「【昵称】正文」格式识别。这类内容不会进记忆库，也不会进生成提示词。

此外微光**全程不拦截消息、不打断事件传播**，所以不会影响树洞或任何其它插件的正常工作。

## 安装

需要 **AstrBot 4.24.2 或更高版本**（4.24.2 起才支持插件自带 Pages 面板）。

```bash
cd AstrBot/data/plugins
git clone https://github.com/yuntaojinghong/astrbot_plugin_proactive_care.git
```

也可以从 [Releases](https://github.com/yuntaojinghong/astrbot_plugin_proactive_care/releases) 下载压缩包，解压后把 `astrbot_plugin_proactive_care` 整个文件夹放进 `data/plugins/`。

插件**没有任何第三方依赖**，不需要额外 `pip install`。

装好后在 WebUI 插件页点一下重载即可。

### 首次使用建议

**默认一句话都不会发出去**，可以放心安装：

- 总开关 `basic.enabled` 默认 **关闭**
- 生效群号列表 `basic.group_whitelist` 默认 **为空**（空 = 不生效）

按这个顺序开：

1. 在配置里填写要启用的群号（建议先只填一个测试群）
2. 打开总开关
3. 打开 `高级 → 演练模式`，观察一两天
4. 在面板「日志」页确认时机和文案都满意后，关掉演练模式

## 指令

| 指令 | 说明 |
| --- | --- |
| `/主动 状态` | 查看总开关、调度器、各闸门当前设置、下次可能开口的时间 |
| `/主动 开启` / `/主动 关闭` | 切换总开关 |
| `/主动 立即` | 立刻生成并发送一条（无视演练模式，管理员专用） |
| `/主动 预览` | 只生成不发送，先看效果 |
| `/主动 暂停` / `/主动 恢复` | 暂停/恢复当前会话 |
| `/主动 概率 30` | 调节「即时搭话」的回复概率（0~100），不带数字则显示当前值 |
| `/记忆 列表` | 查看当前会话的记忆（最多 15 条） |
| `/记忆 搜索 关键词` | 搜索记忆 |
| `/记忆 添加 内容` | 手动添加一条记忆 |
| `/记忆 删除 ID` | 删除指定记忆 |
| `/记忆 清空` | 清空当前会话记忆 |
| `/记忆 整理` | 立刻调用模型抽取一次记忆 |

指令需要 AstrBot 管理员权限。

## 配置面板

基于 AstrBot 原生插件 Pages 机制。在 WebUI 插件页点进插件详情，打开 `dashboard` 页面即可。

六个分区：

- **概览** — 调度器状态、触发方式当前配置、防骚扰闸门一览、接下来的动作倒计时、自检结果、可用模型列表
- **会话** — 每个群的开关、静默时长、下次开口倒计时、今日/累计发送数、记忆条数；可一键预览、立即发送、暂停、重命名、清空上下文、删除
- **记忆** — 搜索、编辑、删除、手动添加、手动触发整理
- **定时** — 可视化编辑定时规则（时间 + 星期 + 补充说明）
- **日志** — 时间轴视图，每条记录都带**触发方式**、**判断依据**、生成的文案、是否有人接话
- **设置** — 分区编辑频率、防骚扰、上下文、记忆、模型与语气、高级选项

面板跟随 AstrBot 的明暗主题，带粒子网络背景与实时倒计时，支持「减少动态效果」偏好。

## 数据与隐私

- 所有数据存在**本机 SQLite**，路径为 `AstrBot/data/plugin_data/astrbot_plugin_proactive_care/proactive_care.db`
- 不使用任何第三方存储服务，不上传任何内容
- 消息上下文每个会话只保留最近 200 条，自动轮转
- **不记录私聊内容**（除非你显式打开私聊开关并配置白名单）

数据放在 AstrBot 的 `data` 目录而不是插件目录，因此插件更新、重装都不会丢数据。

## 常见问题

**装完什么反应都没有？**
检查三件事：总开关是否打开、生效群号列表是否填了群号、群里有没有人说过话（插件需要先看到消息才会建立会话）。

**日志里说「未找到可用模型」？**
到 AstrBot 的「服务提供商」页添加一个对话模型。插件默认使用当前会话的默认模型，不需要额外配置；也可以在面板「设置」里显式指定。

**它在群里话太多 / 太少？**
调 `guard` 那一组。想更安静就调大 `cooldown_minutes` 和 `min_human_gap_minutes`；想更主动就调小 `idle_minutes`。

**会和我其它插件冲突吗？**
不会。微光不拦截消息、不打断事件传播，只是一个旁路监听者。对匿名树洞类插件另有专门的三重隔离（见上文）。

**能不能只在私聊用？**
可以。打开 `basic.enable_private` 并配置私聊白名单即可。但默认关闭——群聊场景的风险更低，也更常见。

**想让它说特定的话？**
改 `llm.style`。那一段是直接写给模型的风格指令，可以按你群的氛围自由调整。

### 几个刻意的技术选择

- **用 SQLite 而不是 JSON 文件**：消息、记忆、发送历史都是持续增长的数据。JSON 方案每写一条都要整体重写，既慢又容易在异常退出时写坏文件。SQLite 提供原子写入、索引与「只更新某一列」的能力，而且 `sqlite3` 是标准库，零依赖。
- **不用向量数据库**：中文场景下「二元字组重叠 + 重要度 + 时间衰减」已经能把最相关的记忆排到前面，而且零依赖、行为可预测、方便写单测。
- **随机排期可复现**：随机关怀的每日时刻表用 `会话ID + 日期` 做随机种子。同一天重启插件得到的排期完全一致，不会因为重启就把当天次数重置掉。
- **测试不需要 AstrBot**：`tests/conftest.py` 里注入了一套最小 AstrBot 桩，CI 在干净环境里也能验证插件能否正常导入与实例化。
